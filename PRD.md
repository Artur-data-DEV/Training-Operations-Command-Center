## 1. Project Charter

### 1.1 Problem Statement

Organizations managing training programs face fragmented processes: room booking happens via email or spreadsheets, enrollment is manual, attendance is tracked informally, and there is no unified visibility into occupancy, no-show rates, or training effectiveness. This creates operational overhead, scheduling conflicts, wasted room capacity, and a poor experience for students and instructors.

### 1.2 Vision

A unified ServiceNow Scoped Application that orchestrates the full lifecycle of training operations — from room reservation through enrollment, attendance, feedback, and analytics — delivered through role-appropriate interfaces for all personas.

### 1.3 Business Outcomes

| Outcome | Measurement |
|---|---|
| Eliminate scheduling conflicts | Room Conflict Rate = 0% |
| Increase room occupancy efficiency | Occupancy Rate > 70% |
| Reduce no-show rate | No-show Rate < 15% |
| Reduce manual approval overhead | Avg Approval Time < 4h |
| Enable self-service enrollment | > 80% enrollments via portal/catalog |
| Improve student experience | Feedback Rating avg > 4.0/5.0 |
| Reduce support volume via VA/KB | VA Deflection Rate > 40% |

### 1.4 Scope

**In Scope:**
- Room management and reservation workflow
- Training session lifecycle management
- Student enrollment, waitlist, and confirmation
- Attendance tracking and no-show handling
- Notification and reminder automation
- Knowledge Base for self-service
- Virtual Agent for common requests
- CMDB light for room resources
- Platform Analytics and operational KPIs
- Service Portal (student/instructor)
- UI Builder Workspace (backoffice/manager)
- Scoped application with full security model

**Out of Scope:**
- External LMS integration (backlog)
- Payment / chargeback processing
- HR system integration (backlog)
- Mobile native app
- Video conferencing platform integration

### 1.5 Success Criteria

- All 5 personas can complete their primary workflows end-to-end
- Zero scheduling conflicts generated by the system
- All critical business rules validated server-side
- ATF coverage ≥ 70% for core Script Includes
- KPI dashboards operational with real data
- Knowledge Base live with minimum 10 articles
- Virtual Agent handling minimum 5 topics
- Go-live checklist fully completed

## 2. Personas

### 2.1 Student
**Description:** An employee who wants to attend training sessions.

**Primary Goals:**
- Discover available training sessions
- Self-enroll via Service Portal or Catalog
- Confirm attendance before deadline
- Cancel enrollment when needed
- Get help via Knowledge Base or Virtual Agent

**Access Level:** Read own records; create enrollment/cancellation requests

---

### 2.2 Instructor
**Description:** Subject-matter expert who delivers training sessions.

**Primary Goals:**
- Request room reservation for a training
- View and manage their own sessions
- Approve or reject student enrollments (when applicable)
- Mark attendance for participants
- View basic session indicators

**Access Level:** Manage own reservations/sessions; read enrollment records for own sessions

---

### 2.3 Backoffice
**Description:** Operations coordinator who manages scheduling and resolves conflicts.

**Primary Goals:**
- Approve or reject room reservation requests
- Manage rooms, resources, and sessions
- Resolve scheduling conflicts and exceptions
- Handle cancellations and edge cases
- Monitor operational dashboards

**Access Level:** Full read/write on operational tables; cannot modify system configuration

---

### 2.4 Training Operations Manager
**Description:** Leadership role focused on performance and strategic decisions.

**Primary Goals:**
- Monitor KPIs (occupancy, no-show, fill rate, approval time)
- Identify bottlenecks and trends
- Evaluate VA and Knowledge effectiveness
- Make data-driven decisions about room and resource allocation

**Access Level:** Read-only on all operational data; full dashboard access

---

### 2.5 Admin
**Description:** ServiceNow platform administrator for this application.

**Primary Goals:**
- Configure master data (rooms, resources, parameters)
- Manage roles, ACLs, and User Criteria
- Maintain CMDB entries
- Configure system parameters via Training Configuration table
- Troubleshoot technical issues

**Access Level:** Full access to all tables and configuration

## 4. Business Rules

> All rules must be validated server-side. Client-side is UX enhancement only.

| ID | Rule | Enforcement |
|---|---|---|
| BR-01 | No room booking with conflicting time slot | BR + Script Include: `RoomAvailabilityService` |
| BR-02 | End date/time must be after start date/time | BR + Data Policy |
| BR-03 | Reservation must meet minimum advance notice | BR + `TrainingConfigService` parameter |
| BR-04 | Expected participants ≤ room capacity | BR + `ReservationValidationService` |
| BR-05 | Reservation approval triggers Training Session creation | BR + Flow + `TrainingSessionService` |
| BR-06 | Reservation cancellation cascades to Training Session | BR + Flow |
| BR-07 | No duplicate enrollment (student + session unique) | BR + `EnrollmentService` |
| BR-08 | No enrollment in cancelled/closed/inactive session | BR + `EnrollmentService` |
| BR-09 | Full session → waitlist or block per config | BR + `EnrollmentService` |
| BR-10 | Approved enrollment decrements available_seats | BR + `EnrollmentService` |
| BR-11 | Cancelled confirmed enrollment increments available_seats | BR + `EnrollmentService` |
| BR-12 | Seat release triggers waitlist promotion | BR → Flow: Waitlist Promotion |
| BR-13 | Late cancellation blocked for Student/Instructor | BR + `TrainingConfigService` |
| BR-14 | Past sessions auto-closed | Scheduled Job: Close Past Sessions |
| BR-15 | Reminder sent 24h before session | Scheduled Job: Send Reminders |
| BR-16 | Confirmation required before deadline | Flow: Attendance Confirmation |
| BR-17 | Unconfirmed seats released after deadline | Scheduled Job: Release Unconfirmed Seats |
| BR-18 | Work notes logged on critical state changes | BR + work note update |

## 5. Non-Functional Requirements

| Category | Requirement |
|---|---|
| Security | All data access enforced via ACLs scoped to `x_tocc` |
| Performance | BRs must not contain queries inside loops; use bulk-safe patterns |
| Maintainability | Script Includes follow SRP; no duplicate logic across artifacts |
| Configurability | All thresholds via `TrainingConfigService` (`sys_properties` override + `x_783010_tocc_a1_training_config` fallback) |
| Observability | Critical state changes logged as work notes; KPI dashboards operational |
| Compatibility | Artifacts must be compatible with `Australia Patch 1 (build 2026-03-31)`; verify on target PDI |
| Portability | Delivered as Update Set / Scoped App installable on any instance |
